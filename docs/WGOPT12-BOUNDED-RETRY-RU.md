# wgopt12 — ограниченный отложенный retry прямого Wi-Fi TX

Основа: аппаратно проверенная wgopt10, commit `44220ec080e5688c896855d41a90f69cd0fcff26`.
Upstream microlink закреплён на `eb63b97073e529d57bc9c1deaeea25ac304034e5`, исходные файлы submodule не изменяются.

## Проблема и доказательства

В wgopt10 обёртка `esp_wifi_internal_tx_by_ref` установила источник части `ERR_MEM`: реальный `ESP_ERR_NO_MEM` Wi-Fi драйвера. В 120-секундном `-P 2` тесте 16 отказов произошли всплеском, при свободной внутренней RAM порядка 36 КБ и без потерь WG RX. Рост STATIC_TX 32→36 в wgopt11 не устранил отказы и уменьшил запас internal heap; базовый размер 32 сохранён.

Цель wgopt12 — не поднять скорость во что бы то ни стало, а не терять WireGuard DATA из-за краткого отказа Wi-Fi-драйвера. Редкий отказ исходного `udp_sendto` не обязательно требует повторной передачи всех данных.

## Одно функциональное изменение

- Только **прямые** WG transport DATA (тип 4); handshake 1–3, send-both, DERP, plaintext RX и маршруты не меняются.
- Подтверждение точного источника: `wg10_wifi_nomem_in_scope()` проверяет текущую FreeRTOS task, STA `ERR_MEM` и raw Wi-Fi `ESP_ERR_NO_MEM` **до** завершения диагностического контекста. Общие `ERR_MEM` не превращаются в retry.
- После подтверждённого отказа сохраняем **одну дополнительную ссылку на исходный зашифрованный `PBUF_RAM`** через `pbuf_ref()`. Отдельной копии ciphertext нет. При возврате вызывающий WireGuard освобождает свою ссылку; очередь владеет второй. Она освобождается при успехе, ошибке, истечении срока и остановке.
- FIFO **8** пакетов, таймер **3 мс**, максимум **2 отложенные попытки**, TTL **50 мс** (включая ожидание). Пакеты, приходящие при backlog, становятся в тот же FIFO. При переполнении возвращаем исходный `ERR_MEM`, не выделяем неограниченную память и не накапливаем задержку.
- `esp_timer` публикует callback через `tcpip_callback`; только TCPIP task вызывает `udp_sendto`. В `sta_linkoutput_hook` не вводятся ожидания, блокировки и изменения packet bytes.
- Повторный `ERR_MEM` помещает запись обратно в начало очереди. При другой ошибке запись освобождается. Остановка отключает новую постановку и очищает все оставшиеся ссылки через синхронизацию TCPIP task. Исходный netif и WireGuard callback не переписываются.
- Новые счётчики `WG12_TX` каждые 10 секунд: `queued, retry_ok, retry_nomem, drop, queue_full, shutdown_free, scheduling_error, deferred_behind`. Приоритет — обнаружение незавершённых отложенных отправок, а не замена одной группы ошибок другой.

## Ограничения и честная интерпретация

Успешный `udp_sendto` или постановка в очередь означает принятие пакета локальной реализацией, **не подтверждает доставку по Wi-Fi или WireGuard**. Даже при FIFO в реализации возможны перестановки относительно других путей/событий вне этой очереди, что допускается WireGuard, но должно быть учтено при тестировании. Не обещается ни ноль отказов, ни прирост Мбит/с. Временные отказы могут быть нормальным давлением TX ресурсов.

Изменён только generated-copy build компонент microlink (`tools/wgopt12_overlay.py`), диагностика, версия и тесты. `RX=128`, `STATIC_TX=32`, `CACHE_TX=32`, crypto, маршрутизация, credentials, OTA slots и NVS остаются прежними.

## Проверки перед аппаратной проверкой

CI запускает все существующие host / security / Wi-Fi / routing / crypto тесты, плюс `tools/test_wgopt12.py`: проверяет размещение scope-блока, тип DATA, источник raw ошибки, FIFO и lifetime очереди; исполняет точный внедряемый C-код с моделями FreeRTOS, lwIP `pbuf`, таймера и `udp_sendto`. Далее — PlatformIO ESP32-S3 OTA-сборка, manifest/provenance и SHA256.

Это экспериментальный кандидат. Пока CI не завершён успешно, BIN не устанавливать.

После успешной сборки сохранить текущий wgopt10 OTA BIN, установить **только OTA application BIN** `firmware-0.1.35-tuya-wgopt12-esp32-s3-ota.bin` через WebUI, без factory/erase/NVS reset/repartition. Проверить WebUI, Tailscale, Tuya/подсеть и журнал. При любом ухудшении вернуть wgopt10 OTA. Массовые `iperf3` прогоны не требуются для первичной проверки корректности.
