# wgdiag3: эксперимент с обслуживанием WG-RX и измерениями TX

Основа: **0.1.35-tuya-wgdiag2** (511f214439063e692394237bbe3c9c1188b5a513); исходный релиз v0.1.35-tuya (3bd26480a4fb82aeb14cf2483bae9d3f2b9c2beb); закреплённый microlink eb63b97073e529d57bc9c1deaeea25ac304034e5. Код исходного submodule не изменён, патчи накладываются только на build-copy. Только OTA application, не factory.

## Основание
Реальный SMB тест: ~680 КБ/с на wgdiag2 (ранее ~700–710 КБ/с). Под нагрузкой direct WG-RX 277 drop за ~132с, HWM очереди 32/32, отдельные серии до 96. В этом же тесте tx_err=0, tx_stage=udp_sendto raw_err=0, поэтому прежние TX ERR_MEM не являются подтверждённой причиной текущего ограничения. Некоторые окна без RX drop также имели низкую скорость; CPU TX или иное ограничение остаётся гипотезой.

## Изменения против wgdiag2
1. **RX scheduler:** в ml_wg_mgr_task сохраняются *оба* 30ms/64-budget drains, peer/disco/periodic, обязательная уступка CPU. Вместо безусловного vTaskDelay(10ms): если хотя бы один WG пакет обработан в текущей итерации или остаётся очередь — **2ms**, иначе **10ms**. Без блокирующей обработки, бесконечных циклов и увеличения очереди. Счётчик `rx_schedule sleep_idle10_delta / sleep_active2_delta` показывает фактический выбор. Это аппаратный эксперимент, НЕ доказанное ускорение.
2. **TX observability:** `timer=tx_lock` измеряет ожидание TX mutex; `timer=tx_crypto` — только вызов шифрования ChaCha20-Poly1305; `timer=tx_send` — от входа в wireguardif_peer_output до возвращения (включая allocation/udp_sendto). У таймеров счётчики, сумма, максимумы и интервалы >30ms; wall time включает вытеснение планировщиком и не равен загрузке CPU. `wire_bytes_delta` по wgi — успешные шифрованные WG-пакеты, с outer-WG-заголовком, но без UDP/IP/Ethernet; не равно SMB goodput. Все счётчики bounded/atomic, без логирования каждого пакета.
3. **Логирование:** только повторяющийся `WG endpoint port flip (NAT-rebind)` переведён в DEBUG. Ни обновление endpoint, ни WireGuard handshake, ни fallback/DERP/RX source не меняются.

Все существующие проверки версии/слота/flash, источников и fail-closed anchors сохранены. WebUI, Tuya Sticky OFF/ON, Remembered/Last Seen/Reserve, DHCP/NVS, SNMP/SSH, Tailscale identity/subnet/exit и OTA не изменялись. Только ESP32-S3, 4MiB flash, 8MiB octal PSRAM, слот OTA 1 966 080 байт. Никаких изменений main/tag/release; устройство не прошивалось.

## Порядок аппаратной проверки и откат
Сохранить рабочий wgdiag2 OTA BIN и SHA256. Проверить скачанный ZIP artifact, совпадение размера и SHA256 `firmware-0.1.35-tuya-wgdiag3-esp32-s3-ota.bin` с SHA256SUMS.txt. Устанавливать исключительно штатным WebUI OTA без erase/NVS wipe. После перезапуска проверить версию, Wi-Fi AP/STA, идентичность Tailscale, работу Tuya и WebUI. Записать 30–40 секунд WG_DIAG без SMB. Затем 90–120 секунд копировать тот же файл из `\\192.168.0.146\d` на домашний ПК тем же путём с выключенным Tailscale на офисном ПК. Сохранить скорость, WG_DIAG в нагрузке и после 20–30 секунд idle. Сравнить с wgdiag2: RX drop_delta, очередь/HWM, rx_wait, rx_schedule, tx_crypto/tx_send/tx_lock, wire_bytes_delta, process/loop/periodic. Потребовать отсутствия boot-loop, watchdog, потери доступа к устройствам. При регрессии через штатный WebUI OTA загрузить сохранённый wgdiag2 application BIN. **Не использовать factory, не сбрасывать NVS**. Если OTA недоступна, остановить испытание и отдельно согласовать восстановление.
